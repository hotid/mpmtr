# Как писать плагины

[English version](WRITING_PLUGINS.md) · справочник: [PLUGINS.ru.md](PLUGINS.ru.md)

Плагин — отдельная программа, которую mpmtr запускает и с которой
переговаривается. Видов два, у них разные задачи и разные каналы:

| | сведения о хопах (`--hop-info`) | проверка приложения (`--app`) |
|---|---|---|
| отвечает на вопрос | «что это за адрес хопа?» | «этот сервер действительно работает?» |
| исполняемый файл | `mpmtr-hop-ИМЯ` | `mpmtr-app-ИМЯ` |
| сколько одновременно | несколько | один |
| канал | строки JSON на stdin / stdout | пакеты JSON на unix-сокете, fd 3 |
| когда спрашивают | один раз на адрес (или каждые `--hop-info-interval`) | каждые `--app-interval` на измеряемый порт |
| влияет на результат | нет, только на то, что показано | да: непройденные проверки делают сервер LOSS или DOWN |

Язык любой. Для Go есть SDK, `github.com/hotid/mpmtr/plugin`; два примера в
`examples/` написаны на Python без него.

## Общее для обоих видов

- **Имя и место.** `--hop-info ИМЯ` запускает `mpmtr-hop-ИМЯ`, `--app ИМЯ` —
  `mpmtr-app-ИМЯ`: сначала рядом с бинарём mpmtr, потом в `PATH`. Имя со
  знаком `/` считается путём.
- **Аргументы.** Всё после имени — ваше:
  `--hop-info "static /etc/inventory.txt"` запустит
  `mpmtr-hop-static /etc/inventory.txt`. Аргументы делятся по пробелам,
  кавычек нет.
- **Один процесс на весь запуск.** mpmtr запускает плагин один раз. То, что
  стоит хранить (соединения, кэши), держите в памяти.
- **Сначала hello, не позже 5 секунд.** Аргументы и файлы проверяйте до
  него: если вместо hello вы завершитесь, mpmtr не стартует и покажет ваш
  stderr.
- **stderr — ваш.** mpmtr хранит последние 20 строк и показывает их, когда
  плагин умирает. В канал пишите только сообщения протокола.
- **Совместимость.** Незнакомые типы сообщений и поля пропускайте.
- **Права.** Плагин работает от того же пользователя, что и mpmtr, часто от
  root. Не доверяйте прочитанному из сети больше необходимого.

## Плагин сведений о хопах

### Что происходит

1. mpmtr запускает все плагины `--hop-info` и ждёт от каждого `hello`.
2. Когда строка с адресом рисуется впервые, mpmtr передаёт этот адрес
   каждому плагину: адреса хопов и адрес назначения.
3. Плагин отвечает именем (`name`), подписью (`note`), обоими или ничем.
4. `name` показывается как `имя (адрес)`, `note` — в колонке `PLUGIN`. Если
   плагинов несколько, берётся имя от первого (в порядке командной строки),
   а подписи склеиваются через пробел.
5. С `--hop-info-interval D` тот же адрес придёт снова, когда вашему ответу
   исполнится столько, — пока строка на экране.
6. В конце mpmtr закрывает ваш stdin. После этого завершайтесь.

### Сообщения

Один объект JSON на строку. Запросы — на stdin, ответы — на stdout.

```
плагин → mpmtr  {"type":"hello","name":"static","version":"1"}
mpmtr → плагин  {"type":"hop","id":4,"addr":"192.0.2.1"}
плагин → mpmtr  {"type":"info","id":4,"name":"core1","note":"rack 12"}
```

### Правила

- **Отвечайте на каждый запрос**, с пустыми `name` и `note`, если ничего не
  знаете. Итоговый отчёт ждёт недостающих ответов (до 10 с).
- **Порядок любой.** Отвечать можно не по порядку; запрос и ответ связывает
  `id`.
- **30 секунд.** Более поздний ответ игнорируется.
- **Сбрасывайте буфер после каждой строки.** stdout — это канал: ответ,
  оставшийся в буфере, не дойдёт.
- **Коротко.** `name` обрезается до 64 символов, каждый столбец `note` — до 120,
  управляющие символы выбрасываются. Колонка не шире 40.
- **Колонки.** Если подпись состоит из частей (интерфейс и счётчик),
  разделите их табуляцией: `"note":"Ethernet1/2\terr:0"`. mpmtr выровняет
  каждую часть по вертикали. Число частей держите одинаковым на всех
  строках; пустую часть отправляйте пустой, а не пропускайте. Не больше 6.
- **Пустой ответ не стирает.** При обновлении пустой ответ оставляет на
  экране то, что вы сказали раньше. Чтобы убрать подпись, скажите что-то
  другое.
- **Адреса приходят из сети.** Любой маршрутизатор на пути сам выбирает
  адрес, с которого отвечает. Если вы где-то ищете адрес, и особенно если
  отправляете при этом учётные данные, решайте по своей конфигурации, какие
  адреса можно опрашивать. mpmtr передаст вам все.
- **Не тормозите всех.** Запросы приходят пачкой, когда заканчивается
  трассировка. Работайте над несколькими сразу, но с ограничением.

### На Go, с SDK

```go
package main

import (
	"context"
	"fmt"
	"net/netip"
	"os"

	"github.com/hotid/mpmtr/plugin"
)

func main() {
	racks := map[netip.Addr]string{netip.MustParseAddr("192.0.2.1"): "rack 12"}
	err := plugin.ServeHops("rack", "1", 8, func(ctx context.Context, a netip.Addr) plugin.HopInfo {
		return plugin.HopInfo{Note: racks[a]}
	})
	if err != nil {
		fmt.Fprintln(os.Stderr, "mpmtr-hop-rack:", err)
		os.Exit(1)
	}
}
```

`ServeHops` говорит hello, читает запросы, выполняет не больше 8 поисков
одновременно (третий аргумент), даёт каждому контекст со сроком 20 секунд и
возвращается, когда mpmtr закрывает stdin. `cmd/mpmtr-hop-snmp` — полный
плагин на его основе.

### Без SDK

`examples/mpmtr-hop-static` (Python) берёт имена и подписи из текстового
файла. Вся его протокольная часть:

```python
say({"type": "hello", "name": "static", "version": "1"})
for line in sys.stdin:                       # кончится, когда mpmtr закроет stdin
    req = json.loads(line)
    if req.get("type") != "hop":
        continue
    name, note = known.get(req["addr"], ("", ""))
    say({"type": "info", "id": req["id"], "name": name, "note": note})
```

где `say` пишет одну строку и сбрасывает буфер.

### Как попробовать руками

Плагину хопов mpmtr для пробы не нужен: подайте ему запросы.

```bash
printf '%s\n' '{"type":"hop","id":1,"addr":"192.0.2.1"}' | ./mpmtr-hop-static inventory.txt
{"type": "hello", "name": "static", "version": "1"}
{"type": "info", "id": 1, "name": "core1", "note": "rack 12, row B"}
```

Затем с mpmtr: `mpmtr -r -c 5 --json --hop-info "./mpmtr-hop-static inventory.txt" ЦЕЛЬ`
— и смотрите `hop_info` в выводе.

## Плагин проверки приложения

### Что происходит

1. mpmtr запускает плагин и ждёт его `hello`.
2. Раз в `--app-interval` (по умолчанию 10 с) для каждого измеряемого порта
   mpmtr открывает настоящее TCP-соединение **с этого порта** к цели.
   Поэтому балансировщик ведёт его на тот же сервер, который измеряют пробы
   этого порта.
3. Если в соединении отказано или на SYN нет ответа, mpmtr записывает это
   сам, вас не вызывают.
4. Иначе mpmtr передаёт вам подключённый сокет вместе с сообщением `check`.
5. Вы говорите по своему протоколу через сокет, закрываете свою копию и
   отвечаете сообщением `result`.
6. mpmtr закрывает последнюю копию с RST и записывает ваш вердикт для этого
   порта и его сервера.

### Сообщения

Дескриптор 3 — unix-сокет `SOCK_SEQPACKET`. Каждое сообщение — один объект
JSON в одном пакете. `check` несёт подключённый TCP-сокет как служебные
данные (`SCM_RIGHTS`).

```
плагин → mpmtr  {"type":"hello","name":"banner","version":"1"}
mpmtr → плагин  {"type":"check","id":7,"src":"192.0.2.1","sport":20031,
                 "dst":"192.0.2.10","dport":443,"server":"S7",
                 "host":"example.com","timeout_ms":5000}
                 + подключённый TCP-сокет
плагин → mpmtr  {"type":"result","id":7,"ok":false,"stage":"handshake",
                 "error":"eof","ms":12.5}
```

- `server` — имя сервера за адресом по версии mpmtr (`--anycast`), иначе
  пусто.
- `host` — цель, как она набрана в командной строке mpmtr, без порта (имя
  или адрес); в SDK это `Request.Host`.
- `timeout_ms` — сколько осталось от `--app-timeout` после соединения.
- `ms` — сколько заняла ваша часть; только для сведения.
- `note` в результате необязателен: несколько символов об ответе (не больше
  24), показываются в колонке `PLUGIN` строки сервера. В SDK это
  `Result.Note`.

### Вердикт

| вы отвечаете | считается как |
|---|---|
| `"ok":true` | пройденная проверка |
| `"ok":false`, любой `stage`, кроме `"plugin"` | непройденная проверка этого сервера (три подряд: DOWN) |
| `"ok":false,"stage":"plugin"` | локальная ошибка: ни пройдена, ни не пройдена |
| ничего за `timeout_ms` + 1 с, либо плагин умер | локальная ошибка |
| ничего на три проверки подряд | плагин останавливается (его сокеты закрываются), отчёт INCOMPLETE |

Поэтому выбор `stage` важен:

- Сервер не заговорил по протоколу, ответил не то или молчал до срока — это
  его неудача. Назовите шаг своими словами (`"handshake"`, `"banner"`,
  `"auth"`): он показывается вместе с неудачей.
- Вы не смогли сделать свою часть (в сообщении нет сокета, ошибка в коде,
  нет файла, недоступно то, от чего зависите вы) — отвечайте
  `"stage":"plugin"`. Проблема плагина не должна выглядеть как потеря в
  сети.

### Правила

- **Проверки идут параллельно.** На каждый измеряемый порт приходит своя;
  отвечайте на каждую с её `id`, в любом порядке. Один медленный сервер не
  должен задерживать остальные.
- **Укладывайтесь в срок.** Поставьте `timeout_ms` на сокет. mpmtr перестаёт
  ждать через секунду после него и считает это локальной ошибкой.
- **Закройте свою копию до ответа.** Последнюю закрывает mpmtr, и именно она
  должна отправить RST.
- **Закрывайте сокеты, которые не будете использовать**: сообщение, которого
  вы не поняли, тоже может нести сокет.
- **Один разговор на проверку.** Сокет каждый раз — новое соединение; не
  храните его.
- **Легче.** Проверка повторяется каждый интервал на каждом измеряемом
  порту, и на её время пробы этого порта приостанавливаются.

### На Go, с SDK

```go
package main

import (
	"bufio"
	"context"
	"errors"
	"fmt"
	"net"
	"os"
	"strings"

	"github.com/hotid/mpmtr/plugin"
)

func main() {
	err := plugin.Serve("http", "1", func(ctx context.Context, c net.Conn, req plugin.Request) plugin.Result {
		if _, err := fmt.Fprintf(c, "HEAD / HTTP/1.0\r\nHost: %s\r\n\r\n", req.Host); err != nil {
			return plugin.Result{Stage: "send", Err: err}
		}
		line, err := bufio.NewReader(c).ReadString('\n')
		if err != nil {
			return plugin.Result{Stage: "answer", Err: err}
		}
		if !strings.HasPrefix(line, "HTTP/") {
			return plugin.Result{Stage: "answer", Err: errors.New("not an HTTP status line")}
		}
		return plugin.Result{OK: true}
	})
	if err != nil {
		fmt.Fprintln(os.Stderr, "mpmtr-app-http:", err)
		os.Exit(1)
	}
}
```

`Serve` говорит hello, принимает сокеты, запускает каждую проверку в своей
горутине со сроком, уже поставленным на соединение и в `ctx`, закрывает
копию плагина и отправляет результат. `cmd/mpmtr-app-http` — это то же самое с заголовком `User-Agent`.

Пример проходит при любой строке состояния HTTP, включая 503: он говорит,
что сервер отвечает по HTTP, а не что сервис здоров. Настоящая проверка
смотрит на то, что ваш сервис обязан ответить.

### Без SDK

`examples/mpmtr-app-banner` (Python) ждёт строку приветствия, которая
начинается с заданного текста (`--app "banner SSH-2.0"`). Неочевидная часть —
приём сокета:

```python
chan = socket.socket(fileno=3)
chan.send(json.dumps({"type": "hello", "name": "banner", "version": "1"}).encode())
while True:
    data, fds, _, _ = socket.recv_fds(chan, 65536, 4)   # сообщение и его сокеты
    if not data:
        break                                            # mpmtr завершился
    conn = socket.socket(fileno=fds[0])
    ...
    conn.close()                                         # до ответа
    chan.send(json.dumps({"type": "result", "id": req["id"], "ok": ok}).encode())
```

На C то же самое — `recvmsg` с управляющим буфером и `CMSG_DATA`.

### Как попробовать

Плагин приложения руками через канал не запустить: ему нужен сокет на
дескрипторе 3. Запускайте его под mpmtr:

```bash
MPMTR_DEBUG_APP=1 mpmtr -r -c 30 --app "./mpmtr-app-banner SSH-2.0" example.com:22
```

`MPMTR_DEBUG_APP=1` печатает в stderr строку на каждую проверку: порт,
установлено ли соединение, ваш вердикт, шаг и время. В отчёте неудачная
проверка видна как `app-failed:N/M` у потока (не прошли N из M).

## Памятка

- [ ] сначала hello, не позже 5 с; аргументы проверены до него
- [ ] в канале только сообщения протокола; диагностика — в stderr
- [ ] на каждый запрос есть ответ с его `id`
- [ ] незнакомые типы сообщений и поля пропускаются
- [ ] плагин хопов: вывод сбрасывается после каждой строки; опрашиваются
      только адреса, разрешённые вашей конфигурацией
- [ ] плагин приложения: срок соблюдён; своя копия сокета закрыта до ответа;
      `"stage":"plugin"` — только для собственных проблем
- [ ] завершается, когда канал закрыт
