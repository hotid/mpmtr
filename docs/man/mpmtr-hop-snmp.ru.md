# ИМЯ

mpmtr-hop-snmp - плагин сведений о хопах для mpmtr: имя маршрутизатора,
интерфейс и его ошибки по SNMP

# СИНТАКСИС

**mpmtr --hop-info** "**snmp** \[**--descr**\] \[**--errors**\] *ФАЙЛ*"
\[*опции*\] *цель*\[:*порт*\]

# ОПИСАНИЕ

**mpmtr-hop-snmp** — плагин **mpmtr**(1). Руками его не запускают:
**mpmtr --hop-info** запускает его сам, передаёт ему адрес каждого
показанного хопа и выводит то, что плагин ответил.

Для адреса хопа плагин спрашивает по SNMP у маршрутизатора с этим
адресом:

- его имя (**sysName**); оно показывается как имя хоста вместо имени из
  обратной зоны DNS;

- интерфейс, которому принадлежит адрес (**ifName**); он показывается в
  колонке **PLUGIN**;

- с **--descr** — описание этого интерфейса (**ifAlias**);

- с **--errors** — ошибки приёма на этом интерфейсе.

``` text
HOST                        ...  PLUGIN
core1.example (192.0.2.1)   ...  Ethernet1/2     «to spine 3»  crc:0
core2.example (192.0.2.5)   ...  Port-Channel37  «uplink»      err:12 +3
```

Адреса хопов приходят из сети, а не от вас: маршрутизатор в любом месте
пути сам выбирает адрес, с которого отвечает. Поэтому плагин ничего не
спрашивает, пока *ФАЙЛ* не разрешит именно этот адрес; см.
**НАСТРОЙКА**.

# ОПЦИИ

Опции плагина пишутся внутри кавычек **--hop-info**, перед именем файла.

**--descr**  
Показывать после имени интерфейса его описание (**ifAlias**) в «».

**--errors**  
Показывать после этого ошибки приёма на интерфейсе; см. **СЧЁТЧИКИ
ОШИБОК**.

*ФАЙЛ*  
Настройка: какие адреса можно спрашивать и как. Обязателен.

# НАСТРОЙКА

Одна строка на префикс: префикс (или один адрес), затем пары
*ключ*=*значение* через пробел. С **\#** начинается комментарий.

``` text
# SNMPv2c: community идёт открытым текстом на каждый спрошенный адрес
10.0.0.0/8      community=public
# SNMPv3 с аутентификацией и шифрованием
192.0.2.0/24    user=monitor auth=sha256:secret-one priv=aes:secret-two
# другой порт и больше терпения для одного медленного устройства
10.1.2.3        community=public port=1161 timeout=3s retries=0
```

<b>community=</b><i>ТЕКСТ</i>  
SNMPv2c с этим community.

<b>user=</b><i>ИМЯ</i>  
SNMPv3 с этим пользователем. Без остального — без аутентификации и без
шифрования.

<b>auth=</b><i>ПРОТОКОЛ</i><b>:</b><i>ПАРОЛЬ</i>  
Аутентификация SNMPv3: **md5**, **sha**, **sha224**, **sha256**,
**sha384**, **sha512**.

<b>priv=</b><i>ПРОТОКОЛ</i><b>:</b><i>ПАРОЛЬ</i>  
Шифрование SNMPv3: **des**, **aes**, **aes192**, **aes256**. Требует
**auth**.

<b>port=</b><i>N</i>  
UDP-порт агента (по умолчанию 161).

<b>timeout=</b><i>D</i>  
Сколько ждать одного ответа (по умолчанию 1s, не больше 10s).

<b>retries=</b><i>N</i>  
Сколько раз запрос повторяется после таймаута (по умолчанию 1, от 0 до
5).

Правила:

- Выигрывает самый длинный подходящий префикс.

- На адрес, не попавший ни в один префикс, не уходит ни одного пакета.

- В строке либо **community**, либо **user**, но не оба.

- Пароли не короче 8 символов и без пробелов (значение кончается на
  первом пробеле).

- Файл не должен читаться группой и остальными (**chmod 600**): в нём
  учётные данные, и файл с более широкими правами плагин не примет.

- Файл без префиксов — ошибка: ничего никогда не будет спрошено.

При любой ошибке в файле плагин печатает номер строки и что в ней не так
в стандартный поток ошибок и завершается.

# ЧТО ОТПРАВЛЯЕТСЯ

На один адрес — не больше двух SNMP-запросов GET, оба на этот адрес.
Таблицы не обходятся. SNMPv3 добавляет обмен, в котором устройство
сообщает свой engine ID.

1.  **sysName.0** и индекс интерфейса для адреса: **ipAddressIfIndex**
    (таблица для IPv4 и IPv6) и, для адреса IPv4, ещё **ipAdEntIfIndex**
    (старая таблица IPv4, для устройств, которые заполняют только её).

2.  Если индекс интерфейса пришёл: **ifName**, с **--descr** ещё
    **ifAlias**, с **--errors** ещё **dot3StatsFCSErrors** и
    **ifInErrors**, всё для этого индекса, одним запросом.

Если устройство знает своё имя, но не знает интерфейс адреса,
показывается только имя. Если оно не отвечает, для этого адреса не
показывается ничего; больше ничего не меняется.

Плагин спрашивает не больше 8 адресов одновременно. Один запрос ждёт
**timeout** и повторяется **retries** раз, так что молчащий адрес стоит
до timeout × (retries + 1): 2 с по умолчанию.

Как часто спрашивать адрес, решает **mpmtr**: один раз, когда хоп
впервые показан. С **--hop-info-interval** *D* адрес, который всё ещё на
экране, спрашивается снова, когда его ответ становится старше этого
интервала. Старый ответ остаётся, пока не придёт новый, а новый пустой
ответ старого не стирает.

# СЧЁТЧИКИ ОШИБОК

С **--errors** примечание заканчивается одним из:

<b>crc:</b><i>N</i>  
Кадры, принятые с неверной контрольной суммой (**dot3StatsFCSErrors**).
Показывается, когда у интерфейса есть этот счётчик: физический порт
Ethernet.

<b>err:</b><i>N</i>  
Все ошибки приёма вместе (**ifInErrors**). Показывается, когда счётчика
контрольных сумм у интерфейса нет: port-channel, VLAN-интерфейс.

ничего  
Устройство не отдаёт ни того, ни другого.

Счётчики идут с загрузки устройства (или с их сброса), поэтому само
число говорит мало. Когда **mpmtr** спрашивает снова
(**--hop-info-interval**), плагин добавляет прирост с того момента, как
сам впервые посмотрел на этот адрес:

``` text
crc:1532 +12
```

значит всего 1532, из них 12 с первого запроса плагина. Счётчик, который
пошёл назад (устройство перезагрузилось, счётчики сбросили), начинает
отсчёт заново. Без **--hop-info-interval** второго запроса нет, и
показывается только общее число.

# КАКОЙ ИНТЕРФЕЙС

Это интерфейс, которому принадлежит адрес, с которого ответил
маршрутизатор. Обычно это интерфейс, через который проба вошла, но
маршрутизатор может ответить с другого интерфейса или с loopback.
Интерфейс, через который трафик уходит, не сообщается.

Хоп на port-channel или VLAN-интерфейсе показывает ошибки этого
логического интерфейса, а не физических портов под ним.

# ПРИМЕРЫ

Имена и интерфейсы:

``` text
mpmtr --hop-info "snmp /etc/mpmtr/snmp.conf" example.com
```

С описаниями и ошибками, обновление раз в минуту:

``` text
mpmtr --hop-info "snmp --descr --errors /etc/mpmtr/snmp.conf" \
      --hop-info-interval 60s example.com
```

Вместе с другим плагином (их примечания стоят рядом):

``` text
mpmtr --hop-info "snmp /etc/mpmtr/snmp.conf" --hop-info rack example.com
```

**1**

**2**  
Неверная командная строка.

# ФАЙЛЫ

**mpmtr** ищет исполняемый файл **mpmtr-hop-snmp** рядом с собой, затем
в **PATH**.

# БЕЗОПАСНОСТЬ

- Community SNMPv2c идёт открытым текстом на каждый адрес, который
  разрешает файл. Держите префиксы не шире своей сети.

- Префикс, покрывающий чужие адреса, отдаёт им community: кто бы ни
  ответил с такого адреса на пути, он получит запрос с ним.

- Сам **mpmtr** ничего для этого не отправляет и опций SNMP не имеет:
  учётные данные живут только в файле.

- Плагин только читает (GET) и ничего не записывает на устройство.
