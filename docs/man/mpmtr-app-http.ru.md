# ИМЯ

mpmtr-app-http - плагин проверки приложения для mpmtr: отвечает ли
сервер по HTTP

# СИНТАКСИС

**mpmtr --app** "**http** \[**--tls**\|**--plain**\] \[**--verify**\]
\[**--get** \[*URL*\]\] \[**--host** *ИМЯ*\] \[**--user-agent**
*ТЕКСТ*\]" \[*опции*\] *цель*\[:*порт*\]

# ОПИСАНИЕ

**mpmtr-app-http** — плагин **mpmtr**(1). Руками его не запускают:
**mpmtr --app http** запускает его сам и передаёт ему соединения. Его
собственные опции пишутся в кавычках после имени.

**mpmtr** измеряет голыми TCP SYN, а они говорят только о том, что
сервер принимает соединения. С этим плагином каждый измеряемый исходный
порт раз в **--app-interval** (по умолчанию 10 с) получает ещё и один
настоящий HTTP-запрос к серверу, на который этот порт ведёт. Сервер,
который соединения принимает, а по HTTP не отвечает, так и виден: его
проверки не проходят, хотя TCP отвечает, и после трёх неудачных проверок
подряд он DOWN.

# ЧТО ДЕЛАЕТ ОДНА ПРОВЕРКА

1.  **mpmtr** открывает обычное TCP-соединение ядра с измеряемого
    исходного порта к цели: те же адреса и порты, что у его проб,
    поэтому балансировщик ведёт соединение на тот же сервер.

2.  Плагин получает установленное соединение. На порту 443 (или с
    **--tls**) он сначала выполняет TLS-рукопожатие с именем цели в
    качестве имени сервера. Затем отправляет

    ``` text
    HEAD / HTTP/1.0
    Host: цель, как она задана mpmtr, без порта
    User-Agent: mpmtr
    ```

3.  Читает одну строку ответа. Строка, которая начинается с **HTTP/**, —
    проверка пройдена, каким бы ни был код ответа.

4.  **mpmtr** закрывает соединение через RST.

Вся проверка должна уложиться в **--app-timeout** (по умолчанию 5 с).

# ОПЦИИ

**--tls**  
Говорить по TLS. Без неё TLS используется только на порту 443.

**--plain**  
Никогда не использовать TLS, в том числе на порту 443.

**--verify**  
Сертификат, не прошедший проверку по имени, делает проверку непройденной
(стадия **tls**). По умолчанию сертификат не проверяется: вопрос в том,
отвечает ли сервер, а не в порядке ли его сертификат.

**--get** \[*URL*\]  
Отправлять **GET** вместо **HEAD**. Некоторые серверы отказывают на HEAD
или отвечают на него иначе (418 или 405 там, где GET получает 200). В
обоих случаях читается только строка статуса. *URL* говорит, что
запрашивать вместо **/**: путь (**/index.php**) или URL с хостом
(**example.com/index.php**, **https://example.com/index.php**). Хост из
URL тогда становится запрашиваемым именем (заголовок **Host** и имя
сервера в TLS), а схема говорит, использовать ли TLS; **--host**,
**--tls** и **--plain** сильнее их. Соединение по-прежнему идёт к цели,
заданной **mpmtr**.

**--host** *ИМЯ*  
Имя для заголовка **Host** и имени сервера в TLS вместо цели, заданной
**mpmtr**.

**--user-agent** *ТЕКСТ*  
Заголовок **User-Agent** (по умолчанию **mpmtr**). Некоторые сайты
отвечают клиенту, которого не считают браузером, иначе, например
перенаправлением на другую версию сайта.

# РЕЗУЛЬТАТЫ

пройдена  
Сервер прислал строку статуса HTTP. Код статуса показывается в колонке
**PLUGIN** строки сервера. Считается ответом этого порта и сервера; RTT
— время TCP-рукопожатия этого соединения.

не пройдена, стадия **tls**  
TLS-рукопожатие не удалось (или, с **--verify**, сертификат не прошёл
проверку).

не пройдена, стадия **send**  
Запрос не удалось отправить (сервер сбросил соединение).

не пройдена, стадия **answer**  
До таймаута не пришло ни строки, сервер закрыл соединение без неё, или
строка не является строкой статуса HTTP.

Проверки считаются отдельно от TCP-проб: непройденная показывается как
<b>app-failed:</b><i>N</i><b>/</b><i>M</i> во флагах и как
**app_failed** из **app_checks** в JSON, со своей долей, и в долю
отказов TCP не входит. Три непройденные проверки подряд делают порт
DOWN, причина **app_down**. Соединение, в котором отказано или которое
не установилось, считает сам **mpmtr**, до плагина оно не доходит.

Чтобы видеть каждую проверку со стадией и текстом ошибки, задайте
**MPMTR_DEBUG_APP=1** и читайте стандартный поток ошибок.

# ЧЕГО ОН НЕ ПРОВЕРЯЕТ

- Код ответа. 404, 500 и перенаправление проходят: проверка отвечает на
  вопрос «жив ли здесь HTTP-сервер», а не «работает ли сайт».

- Сертификат, если не задана **--verify**.

- Больше одного сайта. Каждая проверка запрашивает собственное имя цели;
  другие сайты того же сервера не запрашиваются.

Проверка своего протокола — небольшая программа: см.
**docs/WRITING_PLUGINS.ru.md** в дереве исходников.

# ПРИМЕРЫ

Все маршруты до веб-сервера, каждый измеряемый порт проверяется по HTTP:

``` text
mpmtr --app http example.com:80
```

Все серверы за anycast-адресом, проверка раз в 30 с:

``` text
mpmtr --anycast --app http --app-interval 30s example.com:80
```

# ФАЙЛЫ

**mpmtr** ищет исполняемый файл **mpmtr-app-http** рядом с собой, затем
в **PATH**.

# БЕЗОПАСНОСТЬ

Плагин работает с теми же правами, что и **mpmtr**. Он отправляет только
запрос, показанный выше, и только по соединениям, которые дал ему
**mpmtr**.
