# Серверы за одним адресом

[English version](ANYCAST.md) · [README](../README.ru.md)

Что делает `--anycast` и где он не работает.

## Серверы за anycast-адресом (`--anycast`)

Многие сервисы отвечают с одного адреса многими серверами; балансировщик
выбирает сервер по хэшу адресов и портов соединения, поэтому исходный порт
всё время попадает на один и тот же сервер. `--anycast` различает эти серверы
по их часам TCP timestamp и измеряет каждый, который удалось различить; два
сервера с неразличимыми часами считаются одним.

* **Как различаются серверы.** Каждый SYN несёт опцию TCP timestamp; SYN/ACK
  сервера возвращает его часы (TSval). `TSval − t·Hz (mod 2³²)` постоянно для
  сервера, поэтому ответы собираются в кластеры по серверам. Пробуются
  частоты 1000, 250 и 100 Гц; допуск 50 мс плюс половина кванта SYN-cookie (64
  тика — SYN-cookie хранит только старшие биты часов).

  Кластер считается сервером, только если:
  * он узкий (каждое смещение в пределах допуска от центра),
  * получен с ≥ 2 портов при ≥ 3 ответах,
  * его ответы разнесены во времени (2 × допуск / расстояние до ближайшей
    другой частоты — близкие ответы подходят к часам любой частоты).
* **Перепись.** Один SYN с каждого порта диапазона (в этом режиме по
  умолчанию 20000–22047), 64 в полёте, пока среди последних max(64, 8 ×
  серверов) портов не перестанут появляться и новые серверы, и ответы на
  часах, которых ни у кого нет (сервер, которому балансировщик даёт мало
  портов); затем порты, чей ответ не подошёл ни к одному серверу, опрашиваются
  ещё дважды. Номера серверов (S1, S2, …) закреплены за часами.
* **Измерение.** Каждый сервер получает `--flows` измеряемых портов (начиная
  с меньшего), помимо портов, измеряющих маршруты. Каждый сквозной ответ
  измеряемого порта проверяется по часам его сервера; порт, трижды подряд
  ответивший по часам другого известного сервера, переходит к нему, а у
  сервера, от которого он ушёл, начинает измеряться следующий порт: один
  порт, оказавшийся чужим, ничего не говорит об остальных. Сервер, который
  ни разу не был подтверждён ответом, убирается из списка
  (`phantom_servers_dropped`), когда так ушёл последний его порт: либо
  перепись сложила ответы других серверов в часы, которых ни у кого нет,
  либо сервер вышел из пула балансировщика раньше, чем его начали измерять,
  и его порты достались другим. Отсюда эти два случая не различить. До тех
  пор он остаётся в списке — около трёх интервалов проб на каждый порт.

  Сервер, который просто перестал отвечать, из списка не убирается:
  молчание не говорит, что его не было. Он остаётся в списке и становится
  DOWN.
* **После переписи.** Повторной переписи нет. Сервер, добавленный в пул
  позже, найден не будет: ответы измеряемых портов по часам, которых нет ни
  у одного известного сервера, только считаются
  (`answers_from_unknown_clock`). Его найдёт новый запуск.
* **Экран.** Серверы перечислены под строкой DST маршрута, которым идёт их
  измеряемый порт, каждый со своими сквозными цифрами; Enter открывает его.
  `d` предлагает и `view: servers` — все серверы одним списком (сквозные
  цифры, состояние, измеряемый порт, порты, маршрут, проверки приложения);
  Enter показывает маршрут до выбранного сервера, Esc возвращает к списку.
  Строка адреса показывает перепись (`servers behind the address: 44 …`).
* **Где не работает.** Сервер Linux с `net.ipv4.tcp_timestamps=1` (значение
  по умолчанию) прибавляет к своим часам случайное смещение.
  * Ядра с коммитом 165573e4 (март 2026 года, CVE-2026-23247, есть и в
    стабильных ветках) считают это смещение для каждого соединения: каждый
    порт выглядит как отдельные часы. mpmtr тогда говорит, что серверы
    различить нельзя, и не выдумывает их.
  * Там, где смещение считается на пару адресов (как правило, ядра без
    этого коммита) или его нет вовсе, перепись работает.

  Переписи нет и тогда, когда в ответах нет timestamp (`tcp_timestamps=0`).
* **Свои серверы.** Поставьте `net.ipv4.tcp_timestamps=2` **на серверах**
  (не на хосте, где запущен mpmtr): метки времени остаются, но без
  случайного смещения, поэтому у каждой машины одни часы, какое бы ядро на
  ней ни было. Две машины, чьи часы случайно совпали, по-прежнему считаются
  одной. Настройка действует на новые соединения сразу, перезапускать ничего
  не нужно.

  ```bash
  sudo sysctl -w net.ipv4.tcp_timestamps=2    # на время диагностики
  sudo sysctl -w net.ipv4.tcp_timestamps=1    # вернуть значение по умолчанию
  ```

  Цена: метка времени показывает часы машины как есть, и любой может
  узнать, сколько машина работает с загрузки. Поэтому это настройка на время
  диагностики, а не навсегда.

Перепись видит сервер только через порты, которые ему отдаёт балансировщик:
сервер, которому достаётся очень мало портов диапазона, может быть пропущен,
а другой диапазон портов может его найти.
